# Translations (i18n)

## What it is

Every text the bot shows is a key such as `tags.replies.saved`, with one translation per language. Discord tells the bot each user's client language (`interaction.locale`) and each server's language (`guild.preferredLocale`). It also lets slash command names, descriptions and option choices carry a translation per language.

Supported languages: `en-US` (default, source of all keys) and `pt-BR`.

## What it's for

Members see the bot in their own language, including the `/` menu (`/tag add` appears as `/tag adicionar` for Portuguese users). Typed keys also mean a missing translation fails typecheck instead of shipping a blank message.

## How it works

- **Where translations live.**
  - Each module has `i18n/en-US.ts`, an `as const` object that defines the keys, and `i18n/pt-BR.ts`, typed `Messages['<module>']`.
  - `src/i18n/locales/<locale>.ts` combines all modules under their names, so a key starts with its module (`tags.…`).
  - Shared strings (`errors.*`) live directly in the locale files.
- **Helpers** from `src/i18n/index.ts`:

| Helper | Use |
| --- | --- |
| `translator(locale)` | Returns `tr(key, vars?)` for that language |
| `t(locale, key, vars?)` | One-off translation |
| `localize(builder, prefix)` | Sets name and description (with translations) from `<prefix>.name` / `<prefix>.description`. Works on command, subcommand and option builders |
| `localizations(key)` | A translation map for one key, e.g. option choices |

- **Which language.**
  - Replies use `interaction.locale`.
  - Channel posts and audit-log reasons use `guild.preferredLocale`, because nobody triggered them.
  - Unknown languages fall back to en-US.
- **Placeholders** are `{name}`, filled from `vars`.
- **Command names.**
  - Translated names must be lowercase, 1–32 characters, with no spaces (`apagar_mensagens`).
  - The en-US `name` is the identifier handlers read options by, so treat it as an API.
  - Run `pnpm deploy-commands` after changing any of them.

## Example: translating the `tags` module

This is a simplified version of the real `src/modules/tags/`, which also has `/tag list`, `/tag delete` and autocomplete.

**`src/modules/tags/i18n/en-US.ts`**

```ts
export const tagsEnUS = {
  command: { name: 'tag', description: 'Save and recall text snippets' },
  add: { name: 'add', description: 'Save a tag' },
  show: { name: 'show', description: 'Post a saved tag' },
  options: {
    name: { name: 'name', description: 'Tag name' },
    content: { name: 'content', description: 'Text to save' },
  },
  replies: {
    saved: 'Saved tag **{name}**.',
    exists: 'A tag named **{name}** already exists.',
    notFound: 'No tag named **{name}**.',
  },
} as const;
```

**`src/modules/tags/i18n/pt-BR.ts`**

```ts
import type { Messages } from '@/i18n/types';

export const tagsPtBR: Messages['tags'] = {
  command: { name: 'tag', description: 'Salva e recupera trechos de texto' },
  add: { name: 'adicionar', description: 'Salva uma tag' },
  show: { name: 'mostrar', description: 'Posta uma tag salva' },
  options: {
    name: { name: 'nome', description: 'Nome da tag' },
    content: { name: 'conteudo', description: 'Texto a salvar' },
  },
  replies: {
    saved: 'Tag **{name}** salva.',
    exists: 'Já existe uma tag chamada **{name}**.',
    notFound: 'Nenhuma tag chamada **{name}**.',
  },
};
```

### Registering a module's translations

Add the English object first, because `Messages` is derived from it:

```ts
// src/i18n/locales/en-US.ts
import { tagsEnUS } from '../../modules/tags/i18n/en-US';

export const enUS = {
  // ...existing modules
  tags: tagsEnUS,
} as const;

// src/i18n/locales/pt-BR.ts
import { tagsPtBR } from '../../modules/tags/i18n/pt-BR';

export const ptBR: Messages = {
  // ...existing modules
  tags: tagsPtBR,
};
```

Using the keys:

```ts
localize(new SlashCommandSubcommandBuilder(), 'tags.add');   // /tag add, /tag adicionar
translator(interaction.locale)('tags.replies.saved', { name }); // "Saved tag **rules**."
```

## Example: adding Spanish

1. Add `i18n/es-ES.ts` to every module that has an `i18n/` folder, typed `Messages['<module>']`.
2. Create `src/i18n/locales/es-ES.ts` combining them (copy `pt-BR.ts`).
3. Register it in the `locales` map in `src/i18n/index.ts`: `[Locale.SpanishES]: esES`.
4. Run `pnpm typecheck && pnpm lint`. The structure linter now requires `es-ES.ts` in every module. Then run `pnpm deploy-commands`.

Language codes come from [Discord's locale list](https://discord.com/developers/docs/reference#locales).
